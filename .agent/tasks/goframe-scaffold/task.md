# Task: GoFrame 工程初始化

## Goal

建立一个可编译、可启动的 GoFrame v2 电商项目骨架，包含标准目录结构与配置框架，服务能够启动并监听 HTTP 端口，为后续 MySQL/Redis 接入与业务开发提供基础。

## Scope

允许完成的内容：

- GoFrame v2 工程初始化（模块定义、入口程序）
- GoFrame v2 标准目录结构（api / internal / manifest 等分层骨架）
- 配置框架：支持从配置文件读取，并允许环境变量覆盖关键配置（端口、运行环境等）
- HTTP 服务启动并监听指定端口
- 基础日志输出（启动日志、监听信息）
- 构建与启动说明（如何从干净环境编译与启动）

## Out of Scope

明确本次不处理：

- 任何具体业务模块（商品、订单、用户、分类等）
- MySQL / Redis 的实际接入与连接（下一任务处理）
- 数据库表结构、模型、迁移
- 认证、鉴权及业务中间件
- 依赖环境容器编排（下一任务处理）

## Dependencies

- 无前置任务依赖（本阶段第一个任务）

## Acceptance Criteria

- [ ] AC-001 在全新空白环境中，仅克隆仓库并按说明执行构建命令，工程能成功编译，无缺失依赖或本地特有路径依赖。
- [ ] AC-002 启动服务后，进程正常监听配置指定的 HTTP 端口，不崩溃退出。
- [ ] AC-003 工程目录符合 GoFrame v2 标准目录结构约定，能够直接承载后续业务模块。
- [ ] AC-004 服务配置支持通过环境变量覆盖默认值（如监听端口），无需修改代码即可切换。
- [ ] AC-005 服务启动不依赖任何持久化文件或本地开发机特定状态。

## Relevant Context

- 技术栈：GoFrame v2（Go）。
- 目标是一个电商项目，但本阶段只搭骨架，不实现业务。
- 运行环境为 CNB 云原生开发环境（DinD），环境每日重置：容器关闭、备份卷删除，每次重启都是全新空白环境。因此工程必须可从头重建、配置必须可注入，不能依赖本地持久化状态。

Assumption:
- 采用 GoFrame 官方标准工程结构（api / internal / manifest 分层），后续任务沿用该结构。

## Verification

建议至少执行：

- `go build ./...`（或项目规定构建命令）→ 成功
- `go vet ./...` → 无阻塞问题
- 启动服务并访问监听端口，确认服务存活
