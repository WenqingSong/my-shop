# Task: 健康检查接口与启动验证

## Goal

提供服务健康检查接口，并完成启动级验证：确认服务能够启动、监听端口、连接 MySQL 与 Redis，且健康接口返回正常。

## Scope

允许完成的内容：

- 健康检查接口（返回服务存活状态）
- 启动验证流程：拉起依赖 → 启动服务 → 依赖连通 → 健康接口可用
- 健康接口的响应体包含可识别的存活/状态信息

## Out of Scope

明确本次不处理：

- 任何业务接口（商品、订单、用户等）
- 监控指标、告警体系、可观测性平台接入
- 认证、鉴权
- 健康检查的细粒度子组件探测（数据库写入探测、Redis 读写探测等）

## Dependencies

- 依赖 `goframe-scaffold`（服务骨架）
- 依赖 `infra-mysql-redis`（MySQL / Redis 依赖接入）

## Acceptance Criteria

- [ ] AC-001 服务启动后，访问健康检查接口返回成功（HTTP 200）及可识别的存活状态。
- [ ] AC-002 服务正常启动且 MySQL、Redis 连接成功后，健康检查接口稳定返回“健康”状态。
- [ ] AC-003 从干净环境完整走通链路：拉起依赖容器 → 启动服务 → 服务成功连接 MySQL/Redis → 访问健康接口得到正确结果。
- [ ] AC-004 依赖连接失败时，服务在启动阶段给出明确反馈，而不是以异常状态静默继续对外服务或直接崩溃且无信息。

## Relevant Context

- 运行环境为 CNB 云原生开发环境（DinD），环境每日重置。启动验证必须能在全新空白环境中完整跑通。
- 本阶段目标是“能启动、能验证”，不涉及任何业务能力。

Assumption:
- 健康检查接口作为存活探针（liveness），返回服务存活状态；MySQL/Redis 的连通性在服务启动阶段完成校验。不将健康接口扩展为细粒度 readiness 探测。

## Verification

建议至少执行：

- 拉起依赖容器
- 启动服务，确认启动日志中 MySQL/Redis 连接成功
- 访问健康检查接口，确认返回 200 与健康状态
- 断开依赖后重新启动服务，确认能观察到明确的连接失败反馈
