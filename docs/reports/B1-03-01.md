## 3. Migration 版本与表结构变更

### 3.1 版本

```text
20261110000001_product_spec   20261110000002_user_profile   20261110000003_regions
```

- 均为 14 位当前日期时间戳，严格大于上一批次的 `20261001000024`。
- `up` 版本号无重复（`ls *.up.sql | cut -d_ -f1 | sort | uniq -d` 为空），升序执行。
- 每个版本同时提供 `.up.sql` / `.down.sql`。

### 3.2 表结构变更（真实 MySQL `SHOW CREATE TABLE` 核对）

**1）`product_specs`（规格组）**

| 列 | 类型 | 约束 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | PK |
| `product_id` | BIGINT UNSIGNED | `uk_product_spec_name` 前导列；FK → `products.id` `ON DELETE CASCADE` |
| `name` | VARCHAR(32) NOT NULL | 与 `product_id` 组成 `uk_product_spec_name (product_id, name)` |
| `sort` | INT NOT NULL DEFAULT 0 | 展示排序 |
| `created_at` / `updated_at` | DATETIME | 默认 `CURRENT_TIMESTAMP` / `ON UPDATE` |

**2）`product_spec_values`（规格值）**

| 列 | 类型 | 约束 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | PK |
| `spec_id` | BIGINT UNSIGNED | FK → `product_specs.id` `ON DELETE CASCADE` |
| `value` | VARCHAR(32) NOT NULL | `uk_spec_value (spec_id, value)` |
| `sort` | INT NOT NULL DEFAULT 0 | 展示排序 |
| `created_at` / `updated_at` | DATETIME | 同上 |

额外唯一键 `uk_id_spec (id, spec_id)`：仅用于让 `sku_spec_values` 的复合外键可引用 `(id, spec_id)`。

**3）`sku_spec_values`（SKU↔规格值）**

| 列 | 类型 | 约束 |
| --- | --- | --- |
| `sku_id` | BIGINT UNSIGNED | PK 前导列；FK → `skus.id` `ON DELETE CASCADE` |
| `spec_id` | BIGINT UNSIGNED | PK 第二列（同 SKU 同规格组单值） |
| `spec_value_id` | BIGINT UNSIGNED | 复合 FK `(spec_value_id, spec_id)` → `product_spec_values(id, spec_id)` `ON DELETE RESTRICT` |

索引：PK `(sku_id, spec_id)`、`idx_spec_value (spec_value_id, spec_id)`。

**4）`skus` 增列**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `image_url` | VARCHAR(512) NOT NULL DEFAULT '' | SKU 图；空表示回退 `products.main_image` |
| `spec_signature` | CHAR(32) NULL | 规格组合指纹；NULL 表示无规格/历史 SKU |

新增唯一索引 `uk_product_signature (product_id, spec_signature)`；多个 NULL 允许。

**5）`users` 增列**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `nickname` | VARCHAR(32) NOT NULL DEFAULT '' | 空串=未设置 |
| `avatar_url` | VARCHAR(512) NOT NULL DEFAULT '' | 空串=未设置 |
| `phone` | VARCHAR(20) NULL | NULL=未设置 |

新增唯一索引 `uk_phone (phone)`；多个 NULL 允许。未改 `password_hash`/`status`/`auth_epoch` 及认证代码。

**6）`regions`（地区字典）**

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED AUTO_INCREMENT | PK；导入时显式写原 `system_city.city_id` |
| `parent_id` | BIGINT UNSIGNED NOT NULL DEFAULT 0 | 省级为 0 |
| `level` | TINYINT NOT NULL | 1=省、2=市、3=区/县 |
| `name` | VARCHAR(64) NOT NULL | 地区名称 |
| `created_at` / `updated_at` | DATETIME | 同上 |

索引：`idx_parent (parent_id)`、`idx_level (level)`；无自引用外键、无名称唯一约束（避免阻塞历史数据导入）。

### 3.3 Down 语义（破坏性，已在每个 down 文件顶部说明）

| down | 行为 | 数据影响 |
| --- | --- | --- |
| `20261110000001_product_spec.down.sql` | 删 `sku_spec_values` → `product_spec_values` → `product_specs`，再删 `skus` 两列与唯一索引 | **永久丢失全部规格与 SKU 规格关联**；历史 SKU 行本身（id/name/price/status）保留 |
| `20261110000002_user_profile.down.sql` | 删 `uk_phone`、`phone`、`avatar_url`、`nickname` | **永久丢失已填写的资料与手机号**；账号/密码/状态不受影响 |
| `20261110000003_regions.down.sql` | 删 `regions` | **永久丢失地区字典**（含后续导入数据）；无业务表外键被级联删除 |

## 4. 关键设计选择

1. **商品级规格，不建全局字典**：`product_specs.product_id` 归属商品，运营无需维护全局规格库；
   跨商品复用后续可作为独立演进，不阻塞当前模型。
2. **组合唯一性用 `spec_signature` + `(product_id, spec_signature)` 唯一索引**：
   - 指纹算法：规格值按 `spec_id` 升序，拼成 `"<spec_id>:<spec_value_id>"`，逗号连接后取 MD5 32 位小写 hex。
   - 作用域限定单商品，历史/无规格 SKU 为 NULL，唯一索引允许多 NULL → 兼容与去重同时成立。
   - 不使用「把规格拼进 `name` 再唯一」：`name` 是展示名，可被运营改写，不能作为组合身份。
3. **三重关联约束**：PK `(sku_id, spec_id)` 保证一个 SKU 在一个规格组下单值；复合外键保证规格值属于声明的规格组；
   `idx_spec_value` 支撑「按规格值反查 SKU」。删除策略为「SKU 删除级联、被引用规格值 RESTRICT」，避免静默丢失已售 SKU 的组合。
4. **历史 SKU 不回填**：`image_url` 默认空串、`spec_signature` 为 NULL、不写关联行；不改 `skus.name`、不改 `skus.id` 语义。
5. **用户资料直接加列而非独立表**：与现有 IAM 单表模型一致，认证代码零改动；手机号用 `NULL` 表示未设置，
   不写空串，唯一索引天然允许多个未设置用户。
6. **地区 ID 复用遗留 ID**：`regions.id` 允许显式写入，导入 `system_city.city_id` 时不重新编号，
   避免地址/历史数据二次映射；结构层不建自引用 FK（无法表达省级 `parent_id=0`）。
7. **只做 additive Schema**：不改任何既有列类型/语义，不动库存与秒杀表；应用层读写留到后续任务，避免半成品 API。

### 8.2 已知限制

1. **规格能力只有数据库结构**：`internal/logic/sku`、`api/sku/v1`、`internal/logic/product` 未读写规格表，
   未生成/校验 `spec_signature`，商品详情未返回规格；不构成可用 API。
2. **用户资料只有列**：注册/`GET /me`/资料更新仍未使用 `nickname`/`avatar_url`/`phone`；手机号格式未由 DB 强制。
3. **地区只有结构**：`regions` 无数据、无代码，`addresses` 未加 `region_id`、未建外键。
4. **遗留迁移工具未扩展**：`internal/logic/legacymigrate` 仍只写 `skus(product_id,name,price,status)`，
   已解析的 SKU 图片未落库，规格/地区导入未实现；本报告不声称数据迁移已完成。
5. **down 为破坏性**：规格、资料、地区数据在 down 后不可恢复；生产流程不执行 down，也无自动化 down 门禁。
6. **`.agent/registry/migrations.md` 未更新**：该登记表属于已废弃 Workflow 的分配机制，仍将 `20261001000024` 记为
   `RESERVED` 且未登记本批次三个版本；按任务要求未执行旧 Workflow/Registry 流程，此处登记为已知文档偏差。
7. **未获得真实业务数据验证**：未读取/导入 `tmp/shopping.sql`，规格导入的字段映射只在设计文档中约束，未经真实数据回放。
